# QTR Long — Backtest & Validation Plan

## Цель

Проверить, существует ли у QTR Long устойчивый статистический edge без подгонки стратегии под один участок рынка, один актив или один рыночный режим.

## Базовый принцип

QTR Long не оценивается одним итоговым PnL за длинный период. Результат должен быть устойчив по времени, рыночным режимам и инструментам.

## Этап 1 — Genesis technical run

Первый технический прогон:

- BTCUSDT
- 15m
- 6–12 месяцев истории
- Long Score >= 80
- minimum R:R = 2.0
- BUY only
- без оптимизации параметров

Цель этапа:

- подтвердить корректный поток сигнал → BUY/SKIP → entry → SL/TP;
- исключить lookahead;
- проверить pending-entry и TTL;
- проверить отсутствие SELL;
- убедиться, что стратегия генерирует достаточное число сделок;
- обнаружить технические аномалии до большого прогона.

## Этап 2 — Five-year validation

После успешного Genesis run выполнить основной прогон примерно на 5-летней истории.

Ориентир:

- 2021–2026 YTD
- BTCUSDT 15m
- неизменённая логика Genesis

Результаты обязательно анализировать как за весь период, так и отдельно по годам:

- 2021
- 2022
- 2023
- 2024
- 2025
- 2026 YTD

Нельзя считать стратегию устойчивой только потому, что совокупный результат за пять лет положительный. Нужно проверить, не создан ли весь результат одним сильным годом.

## Этап 3 — Out-of-sample validation

Историю разделить на независимые зоны:

### Development / tuning

2021–2024

Разрешено исследовать и настраивать параметры только на этом участке.

### Validation

2025

Используется для проверки решений, принятых на development-периоде.

### True out-of-sample

2026

2026 не должен использоваться для настройки параметров. Это финальная проверка поведения стратегии на данных, которые не участвовали в разработке.

## Метрики

Минимальный набор метрик:

- Total trades
- Win Rate
- Net PnL
- Profit Factor
- Expectancy
- Average R
- Max Drawdown
- Maximum consecutive losses
- Equity curve
- Score distribution
- Performance for score 80–89
- Performance for score 90+
- Performance by market regime
- Submitted / filled / expired / rejected entries

Дополнительно желательно хранить статистику по месяцам и годам.

## Cross-asset validation

После BTC тот же неизменённый алгоритм проверить минимум на:

- ETHUSDT
- SOLUSDT
- нескольких ликвидных крупных альткоинах

Цель — проверить переносимость логики. Стратегия, которая работает только на одном активе после настройки под него, имеет повышенный риск overfitting.

## Правило против overfitting

Сначала фиксируется Baseline A. Только после получения исходной статистики разрешается менять фильтры, веса Score, R:R, sweep age, OB/FVG правила и другие параметры.

Каждое изменение должно сравниваться с Baseline A по одинаковым данным и метрикам.

## Порядок работ

1. QTR Long backtest wiring.
2. Тест BUY-only backtest boundary.
3. Genesis technical run на 6–12 месяцах BTCUSDT 15m.
4. Проверка корректности сделок и симуляции.
5. Five-year BTC validation.
6. Разбивка по годам и режимам.
7. Development / validation / true out-of-sample.
8. Cross-asset validation.
9. Только после этого — controlled optimization.

## Критерий успеха

Цель бэктеста — не доказать, что QTR Long прибыльный, а попытаться опровергнуть наличие edge максимально честным способом.

Если стратегия сохраняет положительное математическое ожидание, приемлемую просадку и стабильность на разных периодах, режимах и инструментах без чрезмерной подгонки, тогда можно говорить о подтверждённом кандидате на реальный edge.
